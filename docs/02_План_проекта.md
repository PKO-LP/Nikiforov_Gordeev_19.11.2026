# План проекта

**Проект:** Учёт выдачи настольных игр «MyКубик». **Заказчик:** MyКубик. **Авторы:** Никифоров, Гордеев, группа 11ТЭС-26.
**Версия документа:** 1.0. **Дата:** 19.11.2026.

## План спринтов

Всего 3 спринта по 2 недели. На каждый спринт заложено по 12 плановых часов (всего 36 часов на команду из двух человек).

1. **Спринт 1 (недели 1–2). Цель — добавить и увидеть запись.** Выбрать тему, подготовить устав, требования, план и ТЗ, описать поля записи и эскиз окна. Реализовать ввод, проверку обязательных полей и добавление в список словарей Python. Проверить эти действия вручную. Контрольная точка — демонстрация первой рабочей версии (план: 12 ч, ответственные: Никифоров, Гордеев).
2. **Спринт 2 (недели 3–4). Цель — находить и изменять записи.** Реализовать поиск по игре и гостю, фильтрацию по статусу, редактирование записи и смену статусов по правилам; уточнить документацию, проверить новые сценарии и исправить ошибки. Зависит от работающего списка из Спринта 1. Контрольная точка — демонстрация основных сценариев (план: 12 ч, ответственные: Никифоров, Гордеев).
3. **Спринт 3 (недели 5–6). Цель — передать готовый продукт.** Реализовать удаление с подтверждением, провести полные ручные проверки в `tests/manual_checks.md`, сделать скриншоты интерфейса и проверить запуск на другом ПК. Завершить руководство продукта и `README.md`, провести приёмку и подготовить выпуск v1.0. Зависит от функций Спринтов 1 и 2. Контрольная точка — итоговая демонстрация (план: 12 ч, ответственные: Никифоров, Гордеев).

  - Задача 1.2: проектирование структуры словаря записи и макета главного окна Tkinter → Никифоров → 2 ч → зависит от 1.1 → схема интерфейса и полей.

  - Задача 1.4: ручная проверка добавления и пустых полей → Никифоров, Гордеев → 2 ч → зависит от 1.3 → подтверждённая работа функций Спринта 1.
- Готово, когда: форма ввода и список работают без ошибок, пустые обязательные поля блокируются сообщением, документация Спринта 1 сохранена в папке `docs/`.

## Декомпозиция и зависимости

- Иерархическая структура работ (WBS):
  - **1. Проектирование и документация:** Устав → Требования → План проекта → Техническое задание.
  - **2. Базовый интерфейс (Спринт 1):** Главное окно Tkinter → Поля ввода → Проверка обязательных полей → Добавление в список словарей → Отображение в таблице.
  - **3. Основная логика (Спринт 2):** Выбор записи в карточку → Редактирование данных → Поиск и фильтр по статусу → Переключение статуса по правилам.
  - **4. Завершение и приёмка (Спринт 3):** Удаление с подтверждением → Ручное тестирование (`manual_checks.md`) → Скриншоты и документация продукта → Выпуск v1.0.
- Критическая цепочка задач: Проектирование полей и окна (2 ч) → Реализация добавления и списка в `src/main.py` (4 ч) → Реализация выбора записи и редактирования (4 ч) → Реализация смены статусов и поиска (4 ч) → Удаление с подтверждением (2 ч) → Финальное тестирование и приёмка (4 ч).
