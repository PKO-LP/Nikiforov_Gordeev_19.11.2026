**Проект:** Учёт выдачи настольных игр «MyКубик». **Заказчик:** MyКубик. **Авторы:** Никифоров, Гордеев, группа 11ТЭС-26.
**Версия документа:** 1.0. **Дата:** 19.11.2026.

## Назначение и функции

Система предназначена для администраторов клуба настольных игр «MyКубик» и автоматизирует процесс учёта выдачи коробок с играми за игровые столы, контроля их состояния и возврата. Основание — документ `docs/03_Требования.md` (версия 1.0).

Обязательные функции:
- **FR-1:** создание записи о выдаче с присвоением уникального номера и заполнением названия игры, номера стола, имени гостя, времени выдачи и состояния комплекта.
- **FR-2:** отображение общего списка выдач в таблице и вывод подробных данных выбранной записи в поля формы для просмотра.
- **FR-3:** поиск записей по названию игры или имени гостя, а также фильтрация списка по статусу.
- **FR-4:** изменение данных выбранной записи с обязательной проверкой заполнения ключевых полей.
- **FR-5:** перевод статуса записи строго по разрешённой цепочке: «Выдана» → «На проверке» → «Возвращена» или «Выдана» → «На проверке» → «Требует ремонта».
- **FR-6:** удаление выбранной записи только после подтверждения действия пользователем.

## Интерфейс

- Интерфейс: одно главное окно Tkinter (`Учёт выдачи настольных игр «MyКубик»`), разделённое на панель поиска и фильтрации, форму ввода/редактирования с кнопками управления и таблицу списка выданных игр (`ttk.Treeview`). При выборе строки в таблице её данные автоматически загружаются в поля формы.
- Действия:
  - Кнопки управления: «Добавить выдачу», «Сохранить изменения», «Сменить статус», «Удалить запись», «Очистить форму».
  - Поиск и фильтрация: текстовое поле поиска по названию игры или имени гостя, выпадающий список фильтрации по статусу («Все», «Выдана», «На проверке», «Возвращена», «Требует ремонта») и кнопка «Сбросить».
  - Подтверждение удаления: стандартное модальное окно `messagebox.askyesno` перед удалением записи.
- Ошибки: при попытке сохранить пустые обязательные поля, нарушить правила перехода статусов или выполнить действие без выбора записи отображается диалоговое окно `messagebox.showwarning` с понятным описанием причины.
- Макеты: текстовая схема расположения элементов зафиксирована в проектной документации; итоговые скриншоты интерфейса будут размещены в `docs/images/` и `README.md` после сборки программы.

## Данные и реализация

- Стек: Python 3.11+ и стандартная библиотека Tkinter (`tkinter`, `tkinter.ttk`, `tkinter.messagebox`); установка внешних пакетов не требуется.
- Запись: словарь Python со следующими полями:
  - `id` (целое число, обязательное) — уникальный порядковый номер выдачи, генерируется автоматически.
  - `game` (строка, обязательное) — название настольной игры.
  - `table` (строка, обязательное) — номер игрового стола.
  - `guest` (строка, обязательное) — имя гостя, получившего игру.
  - `time` (строка, необязательное) — время выдачи (если не указано, подставляется текущее время или прочерк).
  - `condition` (строка, необязательное) — состояние коробки и компонентов при выдаче (по умолчанию «Полный комплект»).
  - `status` (строка, обязательное) — текущий статус выдачи (по умолчанию «Выдана»).
- Пример записи: `{"id": 1, "game": "Каркассон", "table": "3", "guest": "Алексей", "time": "14:15", "condition": "Полный комплект", "status": "Выдана"}`.
- Хранение: список словарей Python в оперативной памяти во время работы приложения. При запуске программы список пуст, после закрытия окна данные сбрасываются.
- Правила:
  - Обязательные поля при добавлении и редактировании: название игры, номер стола, имя гостя.
  - Допустимые статусы: «Выдана», «На проверке», «Возвращена», «Требует ремонта».
  - Разрешённые переходы статусов: из «Выдана» только в «На проверке»; из «На проверке» в «Возвращена» или «Требует ремонта»; из финальных статусов («Возвращена», «Требует ремонта») переходы запрещены.

## Приёмка

Для проверки готовности системы используются следующие приёмочные тесты (результаты фиксируются в `tests/manual_checks.md`):

- **AT-1 / FR-1:** заполнить обязательные поля (игра, стол, гость) и нажать «Добавить выдачу» → запись с уникальным номером появляется в таблице.
- **AT-2 / NFR-2:** оставить одно из обязательных полей пустым и нажать «Добавить выдачу» → появляется предупреждение, запись не создаётся.
- **AT-3 / FR-2:** кликнуть по строке в таблице → все поля выбранной записи отображаются в форме редактирования.
- **AT-4 / FR-4:** изменить номер стола или состояние у выбранной записи и нажать «Сохранить изменения» → данные в таблице обновляются.
- **AT-5 / FR-3:** ввести часть названия игры в строку поиска или выбрать статус в фильтре → в таблице остаются только подходящие записи.
- **AT-6 / FR-5:** перевести статус записи из «Выдана» в «На проверке», затем в «Возвращена», после чего попробовать изменить статус снова → разрешённые переходы срабатывают, повторное изменение финального статуса блокируется предупреждением.
- **AT-7 / FR-6:** выбрать запись, нажать «Удалить запись» и выбрать «Нет» → запись остаётся; повторить и выбрать «Да» → запись удаляется из списка.
- **AT-8 / NFR-1:** закрыть и заново открыть приложение → список пуст, интерфейс открывается менее чем за 2 секунды.
- Условия сдачи: все обязательные проверки AT-1 — AT-8 пройдены; инструкция в `README.md` проверена; приёмку проводит преподаватель учебной дисциплины по итогам демонстрации версии v1.0.
