# Требования

**Проект:** Учёт выдачи настольных игр «MyКубик». **Заказчик:** MyКубик. **Авторы:** Никифоров, Гордеев, группа 11ТЭС-26.
**Версия документа:** 1.0. **Дата:** 19.11.2026.

## Бизнес-требования

- BR-1: сократить потери времени администраторов при оформлении выдачи и поиске занятых настольных игр в зале.
- BR-2: обеспечить сотрудникам клуба актуальную информацию о том, за каким столом находится каждая игра и проверена ли её комплектация.
- Показатель результата: время поиска информации о выданной игре сокращается с 1–2 минут (поиск в бумажной тетради) до 10 секунд в приложении.

## Функциональные требования

- FR-1: система позволяет создать запись о выдаче с указанием уникального номера, названия игры, номера стола, имени гостя, времени выдачи и состояния комплекта.
- FR-2: система отображает общий список всех выданных игр и показывает полные данные выбранной записи в полях карточки.
- FR-3: система выполняет поиск записи по названию игры или имени гостя, а также фильтрует список по выбранному статусу.
- FR-4: система позволяет редактировать данные выбранной записи с проверкой обязательных полей.
- FR-5: система позволяет изменять статус записи строго по правилам: «Выдана» → «На проверке» → «Возвращена» или «Выдана» → «На проверке» → «Требует ремонта»; остальные переходы запрещены.
- FR-6: система удаляет выбранную запись только после явного подтверждения пользователя в диалоговом окне.

## Нефункциональные требования и ограничения

- NFR-1: список из 10 демонстрационных записей открывается и обновляется не более чем за 2 секунды на стандартном офисном ПК (Windows, Python 3.11+).
- NFR-2: попытка сохранить запись с пустыми обязательными полями (название игры, номер стола, имя гостя) вызывает понятное предупреждение, а некорректная запись не создаётся.
- NFR-3: приложение работает на операционной системе Windows с Python 3.11 и новее без установки сторонних библиотек; элементы интерфейса подписаны на русском языке и читаются без наложений.
- Ограничения: срок разработки — 3 спринта по 2 недели; команда из 2 разработчиков; стек Python + Tkinter; данные хранятся в списке словарей в памяти без использования баз данных; при закрытии окна записи очищаются; в примерах используются только вымышленные данные.
- Дополнительно по желанию: сохранение и загрузка списка выдач из локального JSON-файла (не входит в обязательный объём v1.0).
- Приоритеты: обязательные для v1.0 — FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, NFR-1, NFR-2, NFR-3; по возможности после сдачи базы — сохранение в JSON.
